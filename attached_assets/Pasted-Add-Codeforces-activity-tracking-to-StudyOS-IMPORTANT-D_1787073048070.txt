Add Codeforces activity tracking to StudyOS.

IMPORTANT:
Do not break the existing LeetCode tracking or streak logic.

==================================================
CODEFORCES API INTEGRATION
==================================================

Use the official Codeforces API to determine whether the user solved
at least one Codeforces problem on a particular day.

Use:

https://codeforces.com/api/user.status?handle={HANDLE}

The API returns the user's submissions.

For each submission:

- Check verdict === "OK"
- Use the submission creation timestamp
- Convert the timestamp to the user's local date/timezone
- Consider the day active if the user has at least one accepted submission
  on that date.

Do NOT count:

- Failed submissions
- Compilation errors
- Wrong answers
- Time limit exceeded
- Attempts without an accepted verdict

==================================================
USER CODEFORCES HANDLE
==================================================

Add a Codeforces username/handle to the user's profile/settings.

Example:

Codeforces Handle
[ Nirucoder ]

Provide a way for the user to change it.

Do not require the user to authenticate with Codeforces.

The public Codeforces API is sufficient for checking submissions.

==================================================
STREAK LOGIC
==================================================

Integrate Codeforces activity into the EXISTING coding streak.

A day is considered a coding-active day if:

LeetCode activity exists
OR
Codeforces accepted submission exists.

Therefore:

2026-08-18
LeetCode solved → active day

2026-08-19
Codeforces problem accepted → active day

The streak continues.

If both platforms have activity on the same day:

LeetCode + Codeforces

still count as ONE active day.

Do NOT increment the streak twice.

==================================================
EXAMPLE
==================================================

Monday:

LeetCode: 2 solved
Codeforces: 0

→ Active day

Tuesday:

LeetCode: 0
Codeforces: 1 accepted

→ Active day

Wednesday:

LeetCode: 1 solved
Codeforces: 1 accepted

→ Active day

Thursday:

LeetCode: 0
Codeforces: 0

→ Inactive day

The streak should be calculated from these combined activity dates.

==================================================
API CACHING
==================================================

Do NOT call Codeforces API repeatedly on every render.

Fetch submissions:

- On initial authenticated app load when necessary
- When the Codeforces handle changes
- When refreshing today's activity
- At a reasonable interval if background refresh already exists

Cache the fetched activity.

Use the existing cloud/local sync architecture where appropriate.

==================================================
ERROR HANDLING
==================================================

If:

- Codeforces handle is invalid
- API request fails
- Codeforces is unavailable
- User has not configured a handle

Do NOT break the DSA Tracker or streak system.

Simply treat Codeforces activity as unavailable and continue using
existing LeetCode activity.

Show a small non-blocking status message if appropriate.

==================================================
TIMEZONE
==================================================

This is important.

Do NOT use the Codeforces server date blindly.

Convert the submission timestamp into the user's configured/local
timezone before determining the calendar date.

This prevents a submission around midnight from being assigned to
the wrong day.

==================================================
DUPLICATE SUBMISSIONS
==================================================

A user may submit the same problem multiple times.

Do not count multiple accepted submissions as multiple activities.

For streak purposes:

At least one accepted submission = active day.
